5) Debugger markup language (DML)

Starting with the 6.6.07 version of the debugger, a new mechanism for enhancing output from the debugger and extensions was included: DML.
DML allows output to include directives and extra non-display information in the form of tags.
Debugger user interfaces parse out the extra information to provide new behaviors.

DML is primarily intended to address two issues:
- Linking of related information
- Discoverability of debugger and extension functionality

CmdVariants / ParamsDescription
.dml_startKick off to other DML commands
.prefer_dml.prefer_dml [1 | 0]Global setting: should DML-enhanced commands default to DML?
Note many commands like k, lm, output DML thereafter.
.help /D.help has a new DML mode where a top bar of links is given
.chain /D.chain has a new DML mode where extensions are linked to a .extmatch
.extmatch /D.extmatch has a new DML format where exported functions link to "!ExtName.help FuncName" commands
lmDlm has a new DML mode where module names link to lmv commands
kMk has a new DML mode where frame numbers link to a .frame/dv
.dml_flow.dml_flow StartAddr TargetAddrAllows interactive exploration of code flow for a function.
Builds a code flow graph for the function starting at start address (like uf).
Shows the basic block given the target address plus links to referring and referred blocks.
Example: .dml_flow CreateRemoteThread CreateRemoteThread+30

7) Symbols
CmdVariants / ParamsDescription
ldLoad symbols for Module
ldModuleNameLoad symbols for Module
ld*Load symbols for all modules
!symGet state of symbol loading
!symnoisySet noisy symbol loading (debugger displays info about symbol search)
!symquietSet quiet symbol loading (=default)

x/t ..With data type
x/v ..Verbose (symbol type and size)
x/a ..Sort by address
x/n ..Sort by name
x/z ..Sort by size (function size in memory)
lnList nearest symbols
lnAddrDisplay symbols at or near given address. Useful to identify pointers or call origins.
.sympathDisplay or set symbol search path
.sympath+Append directories to previous symbol path
.symoptDisplay current symbol options
.symopt+FlagsAdd option
.symopt-FlagsRemove option
.symfixSet symbol store path to auto point to Microsoft symbol server
.symfix+DownstreamStoreAppend it to existing path; DownstreamStore = directory for caching symbols
.reloadReload symbol info for all modules
.reload[/f | /v]Force immediate load or verbose mode
.reload[/f | /v] ModuleReload symbols for specified module

Examples:

  • x *! — list all modules
  • x ntdll!* — list all symbols of ntdll
  • x /t /v MyDll!* — list all symbols in MyDll with data type, type, size
  • x kernel32!*LoadLib* — list all symbols in kernel32 containing "LoadLib"
  • .sympath+ C:\MoreSymbols — add symbols from folder
  • .reload /f @"ntdll.dll" — immediately reload symbols for ntdll.dll
  • .reload /f @"C:\WINNT\System32\verifier.dll" — reload symbols for verifier

Also check the "!lmi" command.

11) Process related information
CmdVariants / ParamsDescription
!dml_proc(DML) displays current processes and allows drilling into processes for more info
| (pipe)Print status of all processes being debugged
.tlistList all processes running on the system
!pebDisplay formatted view of process environment block (PEB)

Notes:

  • !peb — dumps formatted PEB info (partial)
  • r $peb — dumps address of PEB (pseudo-register $peb)
  • dt ntdll!_PEB — dumps PEB structure
  • dt ntdll!_PEB @$peb -r — recursively dumps PEB of current process
