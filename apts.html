Advanced Persistent Threats (APTs)

What are APTs?

Advanced Persistent Threats (APTs) are long-term, targeted attacks where an attacker gains unauthorized access to a network and remains undetected for an extended period. APTs often involve sophisticated techniques and are usually carried out by well-funded, organized cybercriminal groups or nation-state actors.

Notable APT Groups

  • APT28 (Fancy Bear) - A Russian cyber espionage group believed to be linked to the Russian government.
  • APT29 (Cozy Bear) - Another Russian-based group, known for its attacks on political targets.
  • Charming Kitten - Iranian APT group known for targeting organizations in the Middle East.
  • Agrius has deployed base64-encoded variants of ASPXSpy to evade detection downloaded some payloads for follow-on execution from legitimate filesharing services such as ufile.io and easyupload.io
  • Ajax Security Team has used FireMalv custom-developed malware, which collected passwords from the Firefox browser storage
  • ALLANITE leverages watering hole attacks to gain access into electric utilities
  • ALLANITE has been identified to collect and distribute screenshots of ICS systems such as HMIs.
  • Andariel has exploited numerous ActiveX vulnerabilities, including zero-days
  • Aoqin Dragon has used the Themida packer to obfuscate malicious payloads
  • Aoqin Dragon has used a dropper that employs a worm infection strategy using a removable device to breach a secure network environment
  • APT-C-23 has masqueraded malware as legitimate applications.
  • APT-C-23 can collect the victim’s phone number, device information, IMSI, etc
  • APT-C-36 has embedded a VBScript within a malicious Word document which is executed upon the document opening
  • APT1 uses two utilities, GETMAIL and MAPIGET, to steal email. GETMAIL extracts emails from archived Outlook .pst files
  • The file name AcroRD32.exe, a legitimate process name for Adobe's Acrobat Reader, was used by APT1 as a name for malware
  • APT12 has exploited multiple vulnerabilities for execution, including Microsoft Office vulnerabilities (CVE-2009-3129, CVE-2012-0158) and vulnerabilities in Adobe Reader and Flash (CVE-2009-4324, CVE-2009-0927, CVE-2011-0609, CVE-2011-0611
  • APT19 used -W Hidden to conceal PowerShell windows by setting the WindowStyle parameter to hidden
  • APT19 sent spearphishing emails with malicious attachments in RTF and XLSM formats to deliver initial exploits. Use cobalt strike and empire
  • APT28 has cleared event logs, including by using the commands wevtutil cl System and wevtutil cl Security
  • APT29 has bypassed UAC
  • APT29 has conducted enumeration of Azure AD accounts

Malware Signatures & YARA Rules

What are Malware Signatures?

Malware signatures are unique identifiers or patterns found within malicious files or network traffic that help security software detect and classify them. These signatures are often based on the file's hash, byte sequences, or behavioral patterns. The goal is to create a pattern that can reliably detect specific malware, without false positives. What are YARA Rules?

YARA is a powerful tool used to detect and classify malware based on patterns or rules. These rules define a set of conditions that describe specific characteristics of a file or behavior, such as strings, byte patterns, and other features that are common to a particular type of malware. YARA is widely used by malware researchers and incident response teams to identify malicious files and behaviors.

Example YARA Rule:


rule Example_Malware_Rule {
    meta:
        description = "Detects example malware based on a specific string pattern"
        author = "Security Researcher"
        last_modified = "2025-04-24"

    strings:
        $malicious_string = "malicious_pattern_here" ascii

    condition:
        $malicious_string
}

In the above example, the YARA rule defines a signature based on the presence of a specific string ("malicious_pattern_here") within a file. If this string is found, the rule will trigger a detection for the malware.

More Example YARA Rule:


rule Suspicious_Malware_Behavior {
    meta:
        description = "Detects suspicious behavior indicative of malware"
        author = "Incident Response Team"
        last_modified = "2025-04-24"

    strings:
        $suspicious_behavior = { 6A 40 68 2A 00 00 00 68 04 00 00 00 } // Specific byte sequence

    condition:
        $suspicious_behavior
}

Malware Classification: Type, Platform, Family, Variant, and Suffixes

Understanding Malware Classification

Malware is often classified using a systematic naming convention that includes several key components:

  • Type: Defines the general category of the malware (e.g., virus, worm, trojan, backdoor).
  • Platform: Indicates the operating system or environment where the malware is designed to operate (e.g., Win32, Linux, MacOS, Android).
  • Family: Refers to a group of malware strains that share similar characteristics or code base. For example, multiple variants of a worm can belong to the same family.
  • Variant: Denotes a specific version or modification of the malware, often indicating a new attack vector or technique.
  • Suffixes: These are additional markers that help in the further classification of malware. For example, ".D" or ".T" can be used to indicate specific behaviors or tactics used by the malware.

Example Classification: Backdoor:Win32/Caphaw.D!lnk

This is an example of a malware classification string:


Backdoor:Win32/Caphaw.D!lnk
  • Type: Backdoor — This indicates that the malware provides unauthorized access to a victim's system, allowing an attacker to control it remotely.
  • Platform: Win32 — The malware is designed for the 32-bit version of the Windows operating system.
  • Family: Caphaw — This refers to the malware family, which typically shares similar behaviors and characteristics.
  • Variant: D — This indicates a specific variant or version of the Caphaw family.
  • Suffix: !lnk — The suffix provides additional context, often related to the file format or method of delivery. In this case, it refers to a malicious shortcut (.lnk) used in the attack.
